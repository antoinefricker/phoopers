# Phase 1c — The Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a coach build a play by hand — place players, drag tokens at an instant to write keyframes, retime them on a multi-track timeline, add steps, screens and branches — and watch it back.

**Architecture:** Pure mutations first, React second. `apps/pwa/src/editor/mutations/` holds functions of the shape `(play, args) => Play` with no React dependency, tested headlessly. `EditorContextProvider` owns the current `Play` and the selection, binds those functions, and hands the play to the existing `PlaybackContextProvider`, which already re-resolves when `play` changes identity. Gestures commit on pointer release, so one `resolveBranch` runs per gesture rather than per frame.

**Tech Stack:** React 19, Mantine 9, SVG, Vitest + Testing Library, the 1a engine at `apps/pwa/src/engine/`, the 1b view at `apps/pwa/src/play2d/`.

**Spec:** [documentation/specs/003-10-10-2026-editor.md](../specs/003-10-10-2026-editor.md)

## Decisions

### Design decisions

Chosen during brainstorming, before the spec was written.

| #   | Chosen                                                                                                         | Rejected, and why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Authoring is scrub-drag-keyframe: move the playhead, drag a token, a keyframe is written there                 | _Formations per step_ — the coach arranges all five players per named step and the engine interpolates. Matches how plays are taught, but keyframes become derived, so a translation layer sits between what is authored and what is stored; a hold is awkward to express through it, and the derived output can reach the conditions behind two recorded limitations without the coach seeing why. _Draw the route then time it_ — a whole path as one stroke, then a start and a duration. Closest to a whiteboard, but the stroke must be sampled into keyframes, the same translation layer with more sampling error. |
| D2  | A new play starts on an empty court, with a "starting formation" button                                        | _Empty only_ — every play begins with ten drags before any authoring happens. _Pre-filled only_ — imposes a roster and a formation, and 3-on-3 or a 4-player drill becomes a deletion exercise.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D3  | The ball is authored by direct manipulation: dropped on a player it attaches, dropped on open court it is free | _A possession band as the input_ — a timeline strip where possession is assigned per interval. Reads well, but it is a second input idiom for one entity. Kept as a **read-only** rendering of the ball's row instead, which is where its value was. _An explicit pass tool_ — invents a "pass" object the model does not have, reintroducing exactly the translation layer D1 rejected.                                                                                                                                                                                                                                  |
| D4  | No undo; the timeline makes keyframes visible and directly correctable                                         | _A state stack_ — push each `Play` on mutation. Cheap because `Play` is pure data, and was the original recommendation. Set aside once the timeline made keyframe errors explicitly correctable rather than blindly reversible. _Inverse commands_ — more code and more failure modes for no benefit at this data size. The residual gap is recorded in [Review Focus](#review-focus) and the spec's Deferred section: a position overwritten by a drag is not recoverable.                                                                                                                                               |
| D5  | Timeline keyframes are fully manipulable — selected, retimed by horizontal drag, deleted                       | _Read and delete only_ — retiming then means delete-and-recreate, and shifting a gesture by 0.3 s is the most common adjustment when pacing a play.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| D6  | A gesture commits on pointer release; during the drag a transient layer previews it                            | _Commit per pointer move_ — `resolveBranch` rebuilds every span's arc-length table, so this runs the whole engine tens of times a second mid-drag.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| D7  | Retiming is **constrained** so an invalid play is unreachable, rather than produced and then reported          | _Validate after the fact_ — `validatePlay` would flag `keyframe-times-not-monotonic` or `keyframe-before-fork` after the user already made the move, teaching them the rule by error message.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D8  | Keyframes are authored without curve handles; paths are straight                                               | _Expose `handleIn`/`handleOut` in 1c_ — the model supports curves and the sample uses them, but tangent-dragging is an interaction of its own and would take a large share of the phase. Deferred explicitly rather than half-built.                                                                                                                                                                                                                                                                                                                                                                                      |
| D9  | One screen with a Play/Edit toggle                                                                             | _A separate `/edit` route_ — the application has no router; introducing one for two modes is disproportionate.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| D10 | Mutations receive generated ids as arguments; the context generates them with `crypto.randomUUID()`            | _Generating ids inside the mutations_ — makes them impure and their tests dependent on mocking a global. Passing the id in keeps every mutation a deterministic function of its arguments.                                                                                                                                                                                                                                                                                                                                                                                                                                |

## Global Constraints

- **Reach for Mantine first, but it is a default rather than a cage.** Compose custom components from Mantine primitives so spacing, colour and dark mode stay consistent. The SVG court and the timeline surface are plain markup by necessity, themed through Mantine's CSS variables.
- **All user-facing strings go through `t('<namespace>.<key>', 'English default')`**, enforced by `i18next/no-literal-string`. Player labels, step names and branch names are DATA and are not translated.
- **Context naming**: `EditorContextProvider` in `EditorContextProvider.tsx`; `useEditorContext` co-located with `EditorContextValue` and `createContext` in `useEditorContext.ts`. The hook throws outside the provider, naming both.
- **No `useState` setter inside `useEffect`** — `react-hooks/set-state-in-effect` is an error.
- **`noUncheckedIndexedAccess` is ON**: `array[i]` and `record[key]` are `T | undefined`. Narrow explicitly — NEVER use `!`.
- **`verbatimModuleSyntax` is ON**: type-only imports are `import type { … }`.
- **`pnpm lint` runs with `--max-warnings 0`** — a warning fails the gate like an error.
- **Coordinates are court metres**, origin at a corner, `x ∈ [0, length]`, `y ∈ [0, width]`. There is no pixel conversion outside the pointer-to-court mapping in Task 6.
- **Mutations never mutate in place.** Every function in `editor/mutations/` returns a new `Play` and leaves its input untouched. This is asserted in every mutation test.
- **The engine is imported only through `engine/index.ts`.**
- Conventional commits, no attribution lines. One commit per task.

## Review Focus

Failure modes the spec implies but whose happy paths no task would otherwise exercise.

1. **Dragging a token on a non-root branch at a time before its fork.** The spec dims that region, but the dimming is presentation; if the commit path does not also refuse it, a UI bug produces a play `validatePlay` rejects with `keyframe-before-fork`. Expect the mutation itself to refuse, not only the pointer handler. → Task 2.
2. **Removing a player still referenced by a screen.** `ScreenEvent` holds `screenerId` and `beneficiaryId`; dropping only the player and their tracks leaves a dangling reference and `unknown-player-reference`. Expect removal to sweep screens too, on every branch. → Task 1.
3. **Removing a branch that has descendants.** `Branch.parentId` means an orphaned grandchild yields `dangling-parent-branch`. Expect the whole subtree to go, and the confirmation to say so. → Tasks 3 and 10.
4. **A non-finite time reaching a mutation.** Pointer maths divides by a bounding-box width that is `0` in jsdom and during layout, so `NaN` can reach `addStep` or `setKeyframe`. The engine does not check `Step.t` or `ScreenEvent.t` for finiteness — see [`Step.t` and `ScreenEvent.t` are not checked for finiteness](../limitations.md#stept-and-screeneventt-are-not-checked-for-finiteness) — so nothing downstream will catch it. Expect mutations to reject a non-finite `t`. → Tasks 2 and 3.
5. **Retiming the last keyframe while the clock sits past the new duration.** Duration is derived, so dragging the final keyframe from 8 s to 4 s with the playhead at 6 s leaves the clock beyond the end. Expect it to clamp. → Task 9.

```ts
// apps/pwa/src/editor/mutations/players.ts
import type { Branch, Play, Player, PlayerId, Vec2 } from '../../engine';
import { COURT_DIMENSIONS } from '../../engine';

// Offense is numbered 1..5 and defense X1..X5, so each side counts on its own. A label is
// never reused: the next free integer is one past the highest in use, which keeps numbering
// stable when a middle player is removed.
export function nextLabel(players: readonly Player[], team: 'offense' | 'defense'): string {
  const used = players
    .filter((p) => p.team === team)
    .map((p) => Number.parseInt(p.label.replace(/^X/, ''), 10))
    .filter((n) => Number.isFinite(n));
  const next = used.length === 0 ? 1 : Math.max(...used) + 1;

  return team === 'offense' ? String(next) : `X${next}`;
}

const centre = (play: Play): Vec2 => {
  const { length, width } = COURT_DIMENSIONS[play.court];

  return { x: length / 2, y: width / 2 };
};

const mapRoot = (play: Play, mutate: (branch: Branch) => Branch): Branch[] =>
  play.branches.map((b) => (b.id === play.rootBranchId ? mutate(b) : b));

// A player placed without a keyframe is absent from the resolved timeline rather than drawn
// at the origin, so the token would simply not appear. Writing t=0 on placement is what keeps
// that unreachable by hand.
export function addPlayer(play: Play, team: 'offense' | 'defense', id: PlayerId): Play {
  const player: Player = { id, team, label: nextLabel(play.players, team) };

  return {
    ...play,
    players: [...play.players, player],
    branches: mapRoot(play, (branch) => ({
      ...branch,
      tracks: { ...branch.tracks, [id]: [{ t: 0, position: centre(play) }] },
    })),
  };
}
```

```ts
export function removePlayer(play: Play, playerId: PlayerId): Play {
  if (!play.players.some((p) => p.id === playerId)) return play;

  return {
    ...play,
    players: play.players.filter((p) => p.id !== playerId),
    branches: play.branches.map((branch) => {
      const tracks = Object.fromEntries(Object.entries(branch.tracks).filter(([key]) => key !== playerId));

      return {
        ...branch,
        tracks,
        screens: branch.screens.filter((s) => s.screenerId !== playerId && s.beneficiaryId !== playerId),
      };
    }),
  };
}
```

The ball's track survives this filter because its key is the literal `'ball'`. A ball keyframe attached to the removed player is NOT swept — `attachedTo` pointing at a departed player is caught by `validatePlay` as `unknown-player-reference`, and Task 10's issue panel is how the coach sees it. Sweeping it silently would delete authored possession the coach may want to reassign.

```ts
// in players.ts
import { FORMATION } from '../formation';

export type FormationIds = { offense: PlayerId[]; defense: PlayerId[] };

// Builds the whole roster in one pass rather than calling addPlayer ten times, so the ball
// can be attached in the same immutable step and the result is valid at once.
export function applyFormation(play: Play, ids: FormationIds): Play {
  const players: Player[] = [];
  const tracks: Record<string, { t: number; position?: Vec2; attachedTo?: PlayerId }[]> = {};

  for (const team of ['offense', 'defense'] as const) {
    const positions = FORMATION[team];
    ids[team].forEach((id, index) => {
      const position = positions[index];
      if (position === undefined) return;
      players.push({ id, team, label: nextLabel([...play.players, ...players], team) });
      tracks[id] = [{ t: 0, position }];
    });
  }

  const pointGuard = ids.offense[0];
  if (pointGuard !== undefined) tracks.ball = [{ t: 0, attachedTo: pointGuard }];

  return {
    ...play,
    players: [...play.players, ...players],
    branches: mapRoot(play, (branch) => ({ ...branch, tracks: { ...branch.tracks, ...tracks } })),
  };
}
```

```ts
// apps/pwa/src/editor/mutations/keyframes.ts
import type { Branch, BranchId, EntityId, Keyframe, Play, PlayerId, Vec2 } from '../../engine';

// A child branch inherits everything before its fork from its ancestors, and a keyframe
// earlier than the fork is invalid (`keyframe-before-fork`). The editor refuses such a write
// here as well as dimming the region, so a presentation bug cannot produce an invalid play.
export function forkTimeOf(play: Play, branchId: BranchId): number {
  const branch = play.branches.find((b) => b.id === branchId);
  if (branch === undefined || branch.forkStepId === null) return 0;

  for (const candidate of play.branches) {
    const step = candidate.steps.find((s) => s.id === branch.forkStepId);
    if (step !== undefined) return step.t;
  }

  return 0;
}

const writable = (play: Play, branchId: BranchId, t: number): boolean =>
  Number.isFinite(t) && t >= 0 && t >= forkTimeOf(play, branchId);

const mapBranch = (play: Play, branchId: BranchId, mutate: (branch: Branch) => Branch): Play => ({
  ...play,
  branches: play.branches.map((b) => (b.id === branchId ? mutate(b) : b)),
});

// Keyframes are stored in ascending time order; every writer goes through this so the model's
// monotonic ordering is a property of the module rather than of each call site.
const upsert = (keyframes: readonly Keyframe[], next: Keyframe): Keyframe[] =>
  [...keyframes.filter((k) => k.t !== next.t), next].sort((a, b) => a.t - b.t);

function writeKeyframe(play: Play, branchId: BranchId, entityId: EntityId, next: Keyframe): Play {
  if (!writable(play, branchId, next.t)) return play;

  return mapBranch(play, branchId, (branch) => ({
    ...branch,
    tracks: { ...branch.tracks, [entityId]: upsert(branch.tracks[entityId] ?? [], next) },
  }));
}

export const setKeyframe = (play: Play, branchId: BranchId, entityId: EntityId, t: number, position: Vec2): Play =>
  writeKeyframe(play, branchId, entityId, { t, position });
```

```ts
export function moveKeyframe(play: Play, branchId: BranchId, entityId: EntityId, fromT: number, toT: number): Play {

  const current = branch?.tracks[entityId] ?? [];
```

```ts
// apps/pwa/src/editor/mutations/structure.ts
import type { Branch, BranchId, Play, PlayerId, ScreenId, Step, StepId } from '../../engine';
import { forkTimeOf } from './keyframes';

const mapBranch = (play: Play, branchId: BranchId, mutate: (b: Branch) => Branch): Play => ({
  ...play,
  branches: play.branches.map((b) => (b.id === branchId ? mutate(b) : b)),
});

// Steps are kept in ascending time order so the transport's marks and the ruler read the same
// sequence without either having to sort.
const ordered = (steps: readonly Step[]): Step[] => [...steps].sort((a, b) => a.t - b.t);

export function addStep(play: Play, branchId: BranchId, t: number, name: string, id: StepId): Play {
  if (!Number.isFinite(t) || t < 0 || t < forkTimeOf(play, branchId)) return play;

  return mapBranch(play, branchId, (b) => ({ ...b, steps: ordered([...b.steps, { id, t, name }]) }));
}

const mapStep = (play: Play, stepId: StepId, mutate: (s: Step) => Step): Play => ({
  ...play,
  branches: play.branches.map((b) => ({
    ...b,
    steps: ordered(b.steps.map((s) => (s.id === stepId ? mutate(s) : s))),
  })),
});

export const renameStep = (play: Play, stepId: StepId, name: string): Play =>
  mapStep(play, stepId, (s) => ({ ...s, name }));

export function moveStep(play: Play, stepId: StepId, t: number): Play {
  if (!Number.isFinite(t) || t < 0) return play;

  return mapStep(play, stepId, (s) => ({ ...s, t }));
}

// A step that a branch forks from cannot be removed: dropping it orphans that branch, which
// `validatePlay` reports as `fork-step-not-in-ancestors`. Removing the branch first is the
// way to remove such a step.
export function removeStep(play: Play, stepId: StepId): Play {
  if (play.branches.some((b) => b.forkStepId === stepId)) return play;

  return {
    ...play,
    branches: play.branches.map((b) => ({ ...b, steps: b.steps.filter((s) => s.id !== stepId) })),
  };
}
```

```ts
const ancestorChain = (play: Play, branchId: BranchId): Branch[] => {
  const chain: Branch[] = [];
  let current = play.branches.find((b) => b.id === branchId);

  // Guarded by the branch count: a cycle in parentId would otherwise spin here, and
  // `validatePlay` reports `branch-cycle` rather than preventing one.
  while (current !== undefined && chain.length <= play.branches.length) {
    chain.push(current);
    const parentId = current.parentId;
    current = parentId === null ? undefined : play.branches.find((b) => b.id === parentId);
  }

  return chain;
};

export function forkBranch(play: Play, parentBranchId: BranchId, forkStepId: StepId, name: string, id: BranchId): Play {
  const onChain = ancestorChain(play, parentBranchId).some((b) => b.steps.some((s) => s.id === forkStepId));
  if (!onChain || play.branches.some((b) => b.id === id)) return play;

  return {
    ...play,
    branches: [
      ...play.branches,
      { id, parentId: parentBranchId, forkStepId, name, tracks: {}, steps: [], screens: [] },
    ],
  };
}

export function descendantsOf(play: Play, branchId: BranchId): BranchId[] {
  const direct = play.branches.filter((b) => b.parentId === branchId).map((b) => b.id);

  return direct.flatMap((child) => [child, ...descendantsOf(play, child)]);
}

export function removeBranch(play: Play, branchId: BranchId): Play {
  if (branchId === play.rootBranchId) return play;
  const doomed = new Set<BranchId>([branchId, ...descendantsOf(play, branchId)]);

  return { ...play, branches: play.branches.filter((b) => !doomed.has(b.id)) };
}
```

```ts
// apps/pwa/src/editor/constraints.ts
import type { BranchId, EntityId, Play, Step } from '../engine';
import { snapToStep } from '../play2d/transportMath';
import { forkTimeOf } from './mutations';

// Keyframes may not cross: the model requires ascending times. A keyframe is therefore
// confined to the open interval between its neighbours, less a hair so it never lands exactly
// on one and collides.
const EPSILON = 1e-3;

export function retimeBounds(
  play: Play,
  branchId: BranchId,
  entityId: EntityId,
  t: number,
): { min: number; max: number } {
  const track = play.branches.find((b) => b.id === branchId)?.tracks[entityId] ?? [];
  const times = track.map((k) => k.t).sort((a, b) => a - b);
  const index = times.indexOf(t);
  const floor = forkTimeOf(play, branchId);
  const previous = index > 0 ? times[index - 1] : undefined;
  const next = index >= 0 && index < times.length - 1 ? times[index + 1] : undefined;

  return {
    min: previous === undefined ? floor : previous + EPSILON,
    max: next === undefined ? Infinity : next - EPSILON,
  };
}

export function constrainRetime(
  play: Play,
  branchId: BranchId,
  entityId: EntityId,
  fromT: number,
  desiredT: number,
  steps: readonly Step[],
  snapThreshold: number,
): number {
  const { min, max } = retimeBounds(play, branchId, entityId, fromT);
  const wanted = Number.isFinite(desiredT) ? desiredT : fromT;
  const snapped = snapToStep(wanted, steps, snapThreshold);

  return Math.min(Math.max(snapped, min), max);
}
```

```ts
// apps/pwa/src/editor/pointer.ts
import type { Play, PlayerId, ResolvedTimeline, Vec2 } from '../engine';
import { COURT_DIMENSIONS, stateAt } from '../engine';

export function clampToCourt(point: Vec2, court: Play['court']): Vec2 {
  const { length, width } = COURT_DIMENSIONS[court];
  if (!Number.isFinite(point.x) || !Number.isFinite(point.y)) {
    return { x: length / 2, y: width / 2 };
  }

  return {
    x: Math.min(Math.max(point.x, 0), length),
    y: Math.min(Math.max(point.y, 0), width),
  };
}

// The SVG viewBox is in court metres, so the inverse screen CTM maps a client point straight
// into court space with no scale factor of our own. Without layout — jsdom, or a hidden
// canvas — there is no CTM, and clampToCourt turns the resulting NaN into the court centre.
export function courtPointFromEvent(
  event: { clientX: number; clientY: number },
  svg: SVGSVGElement | null,
  court: Play['court'],
): Vec2 {
  const ctm = svg?.getScreenCTM?.()?.inverse();
  if (svg === null || ctm === undefined || ctm === null) {
    return clampToCourt({ x: Number.NaN, y: Number.NaN }, court);
  }

  const origin = svg.createSVGPoint();
  origin.x = event.clientX;
  origin.y = event.clientY;
  const mapped = origin.matrixTransform(ctm);

  return clampToCourt({ x: mapped.x, y: mapped.y }, court);
}

// Which player is under the drop point at this instant. Asking the engine rather than reading
// keyframes means an attached ball and a mid-span position both resolve correctly.
export function dropTargetAt(timeline: ResolvedTimeline, t: number, point: Vec2, radius: number): PlayerId | null {
  const state = stateAt(timeline, t);
  let best: PlayerId | null = null;
  let bestDistance = radius;

  for (const [id, player] of Object.entries(state.players)) {
    const dx = player.position.x - point.x;
    const dy = player.position.y - point.y;
    const distance = Math.hypot(dx, dy);
    if (distance <= bestDistance) {
      best = id as PlayerId;
      bestDistance = distance;
    }
  }

  return best;
}
```

```tsx
export function CourtEditLayer() {
  const { play, setKeyframe, attachBall, releaseBall } = useEditorContext();
  const { timeline, branchId, currentTimeRef } = usePlaybackContext();
  const svgRef = useRef<SVGSVGElement | null>(null);
  // The in-flight gesture. A ref, not state: it changes per pointer move and must not render.
  const dragRef = useRef<{ entityId: EntityId } | null>(null);
  const ghostRef = useRef<SVGGElement | null>(null);

  const editableNow = () => currentTimeRef.current >= forkTimeOf(play, branchId);

  const onPointerDown = (entityId: EntityId) => (event: React.PointerEvent) => {
    if (!editableNow()) return;
    event.currentTarget.setPointerCapture(event.pointerId);
    dragRef.current = { entityId };
  };

  const onPointerMove = (event: React.PointerEvent) => {
    if (dragRef.current === null) return;
    const point = courtPointFromEvent(event, svgRef.current, play.court);
    // Ref-driven, exactly as the 1b token layer does: no setState during a gesture.
    ghostRef.current?.setAttribute('transform', `translate(${point.x} ${point.y})`);
  };

  const onPointerUp = (event: React.PointerEvent) => {
    const drag = dragRef.current;
    dragRef.current = null;
    if (drag === null) return;
    const t = currentTimeRef.current;
    const point = courtPointFromEvent(event, svgRef.current, play.court);

    if (drag.entityId === 'ball') {
      const target = dropTargetAt(timeline, t, point, BALL_SNAP_RADIUS);
      if (target === null) releaseBall(branchId, t, point);
      else attachBall(branchId, t, target);
      return;
    }

    setKeyframe(branchId, drag.entityId, t, point);
  };
  // …render one <g data-testid={`edit-token-${id}`}> per entity, plus the ghost…
}
```

`BALL_SNAP_RADIUS` is `1.2` court metres — a little over a token's own radius, so a drop that
visually lands on a player attaches rather than falling to the floor beside them.

```ts
// apps/pwa/src/editor/timelineGeometry.ts
import type { EntityId, Keyframe, ResolvedTimeline } from '../engine';

export interface TimelineRowModel {
  entityId: EntityId;
  label: string;
  team: 'offense' | 'defense' | 'ball';
  keyframes: Keyframe[];
}

export function fractionOf(t: number, duration: number): number {
  if (!(duration > 0) || !Number.isFinite(t)) return 0;

  return Math.min(Math.max(t / duration, 0), 1);
}

// Reads `anchors`, which carries each entity's keyframes, NOT `spans`: a prepared span
// substitutes {0,0} for an attached ball endpoint, so building rows from spans would draw the
// ball's markers at the court corner.
export function rowsOf(timeline: ResolvedTimeline): TimelineRowModel[] {
  const players: TimelineRowModel[] = timeline.players.map((player) => ({
    entityId: player.id,
    label: player.label,
    team: player.team,
    keyframes: timeline.anchors[player.id] ?? [],
  }));

  return [...players, { entityId: 'ball', label: 'ball', team: 'ball', keyframes: timeline.anchors.ball ?? [] }];
}
```

The ball row's `label` is the literal `'ball'` and is NOT rendered as text — the row is labelled
in the UI through `t('play.editor.ballRow', 'Ball')`. Keeping the model free of translated text
is what lets `rowsOf` stay pure.

```ts
// in timelineGeometry.ts
export function timeFromClientX(clientX: number, rect: DOMRect, duration: number): number {
  if (!(rect.width > 0) || !(duration > 0)) return 0;
  const fraction = (clientX - rect.left) / rect.width;
  if (!Number.isFinite(fraction)) return 0;

  return Math.min(Math.max(fraction, 0), 1) * duration;
}
```

```ts
    // The ball: held by 1, passed to 2 at t=3, shot at t=5.
    play = attachBall(play, ROOT, 0, one);
    play = attachBall(play, ROOT, 3, two);
    play = releaseBall(play, ROOT, 5, { x: 26.4, y: 7.5 });

    const step = 'step-entry' as StepId;
    play = addStep(play, ROOT, 2, 'Entry pass', step);

    play = addScreen(play, ROOT, 2, two, one, 'screen-1' as ScreenId);

    const variant = 'variant' as BranchId;
    play = forkBranch(play, ROOT, step, 'Switch', variant);
    // A keyframe on the variant, after the fork at t=2.
    play = setKeyframe(play, variant, one, 4, { x: 24, y: 12 });

    expect(validatePlay(play)).toEqual([]);
    expect(play.branches).toHaveLength(2);
    expect(play.branches.find((b) => b.id === ROOT)?.steps).toHaveLength(1);
    expect(play.branches.find((b) => b.id === ROOT)?.screens).toHaveLength(1);
    expect(play.branches.find((b) => b.id === ROOT)?.tracks.ball).toHaveLength(3);

    // It resolves and samples: the play is watchable, not merely well-formed.
    const timeline = resolveBranch(play, variant);
    expect(timeline.duration).toBeGreaterThan(0);
    expect(stateAt(timeline, 4).players[one]?.position).toEqual({ x: 24, y: 12 });
  });

  it('refuses a keyframe on the variant before its fork', () => {
    let play = applyFormation(emptyPlay, { offense, defense });
    const step = 'step-entry' as StepId;
    const [one] = offense;
    if (one === undefined) throw new Error('bad fixture');
    play = addStep(play, ROOT, 2, 'Entry pass', step);
    const variant = 'variant' as BranchId;
    play = forkBranch(play, ROOT, step, 'Switch', variant);

    const attempted = setKeyframe(play, variant, one, 1, { x: 5, y: 5 });

    expect(attempted).toEqual(play);
    expect(validatePlay(attempted)).toEqual([]);
  });

  it('adds a player beyond the formation without breaking validity', () => {
    const play = addPlayer(applyFormation(emptyPlay, { offense, defense }), 'offense', 'o6' as PlayerId);

    expect(play.players).toHaveLength(11);
    expect(play.players.at(-1)?.label).toBe('6');
    expect(validatePlay(play)).toEqual([]);
  });
});
```

## Verification

`make ci` is the gate: lint, typecheck, `i18n:check`, tests and build.

Beyond it, the spec's acceptance criterion is a manual check, because it is about whether the
thing is usable rather than whether it is correct: open the app, switch to Edit, press "New
play", and build a play from an empty court — players on both teams, motion authored by
dragging, a ball passed and shot, a named step, a screen, and a variant forked from that step —
then switch to Play and watch it back. The issue panel should read "No problems" at the end.

The automated acceptance test in Task 10 covers the same sequence at the model layer. It cannot
cover whether the gestures are usable, which is the whole reason the manual pass exists.
